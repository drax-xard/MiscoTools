# Dilstout

**Naughty Tongue** — a portable, offline random name generator that mixes real language
packs to produce person, place, organization, and domain names.

Dilstout is part of [MiscoTools](../README.md). It follows the same house style as the other
tools: no build step, no runtime dependencies, no telemetry, and everything local.

> Status: Milestone 3 complete — browser mixer, results with provenance, preset gallery, and
> the LAP Studio. 65 core, pack, and UI-helper tests, plus a headless Chrome smoke test.
>
> Future: a native embeddable SDK (C ABI + C++ wrapper, later Python/WASM) is planned as M8,
> after all current milestones. See [the roadmap](docs/ROADMAP.md).

## Why

Most name generators either pull from a single shallow word list or produce generic fantasy
syllables. Dilstout instead treats each culture's naming system as a **Language Pack (LAP)**
with explicit phonology, morphology, and naming conventions. Packs can be weighted and mixed,
so a 50/50 Babylonian/Aztec blend is a first-class operation rather than a novelty.

## Features

- **Language Packs (`.lap`)** — phonology, lexicon, name forms, naming conventions, and
  category templates for a language or culture (for example Ancient Babylonian and Aztec).
- **Categories** — person names, location names, organization names (religious, political,
  military, guild), and domain names (nation, kingdom, empire, province, district, town).
- **Pack Mixer** — combine multiple LAPs with independent weights and per-category overrides.
- **Preset Gallery** — save and load mixes as `.lpp` (Language Pack Preset) files.
- **LAP Studio** — schema-driven editor for authoring packs, with a short guide on how to
  research a culture and where to collect the data.
- **Extensible by design** — mixing strategies, renderers, slot resolvers, categories,
  importers, and (later) speakers are registered through a plug-in API.
- **Portable** — static web app with no backend; serve the folder from any static host, a
  `python3 -m http.server`, or the planned optional Tauri wrapper. No install and no telemetry.

## Using the app

```sh
cd Dilstout
python3 -m http.server 8000
```

Open <http://localhost:8000/>. Add or open packs in the Mixer, set weights and per-category
overrides, then generate. Results keep per-name provenance and phonemes. The Gallery saves
mixes to this browser as `.lpp` presets and exports them as files. The LAP Studio edits a pack
through a schema-driven form with live validation and preview.

## Bundled packs

| Pack | Culture | Status |
|---|---|---|
| `packs/ancient-babylonian.lap` | Akkadian / Old Babylonian | experimental |
| `packs/aztec.lap` | Nahua / Mexica (Classical Nahuatl) | experimental |
| `packs/test-synthetic.lap` | Invented engine fixture | test only |

Both real packs include IPA inventories, ASCII romanization tables, prosody, join rules,
sources, and a license note. They model naming patterns, not fluent language, and are marked
experimental until a specialist reviews them. `presets/babylonian-aztec-50-50.lpp` is the
reference mixed preset.

## Layout

```
Dilstout/
  index.html
  manifest.webmanifest
  sw.js
  core/            # RNG, engine, mixing, validation, morphology (UI-agnostic)
  ui/              # mixer, gallery, studio, results
  plugins/         # example plug-ins
  packs/           # bundled .lap files
  presets/         # bundled .lpp files
  schemas/         # JSON Schemas for .lap, .lpp, plug-in manifests
  docs/            # DESIGN.md, ROADMAP.md, authoring and plug-in guides
  tests/           # node --test, no dependencies
```

## Formats

| Extension | Contents |
|---|---|
| `.lap` | Language Pack: UTF-8 JSON, versioned, validated by `schemas/lap.schema.json`. |
| `.lpp` | Language Pack Preset: UTF-8 JSON, list of packs with weights/overrides, seed, strategy, renderer. |

Both formats are plain JSON so they can be inspected, diffed, and generated by scripts.

## Development

The app has no runtime dependencies. Serve the folder over HTTP (ES modules and `fetch` do
not work from `file://`). Tests need Node 22.14 or newer because the schemas are loaded as JSON
modules.

```sh
cd Dilstout
node --test                 # 65 core, pack, and UI-helper tests
python3 -m http.server 8000 # serve the app during development
```

An optional browser smoke test drives the real UI. It starts a temporary static server and
needs Chrome, Python 3, and Playwright Core installed outside the app:

```sh
npm install --no-save playwright-core
npm run test:browser
```

Set `CHROME_PATH` if Chrome is not at `/usr/bin/google-chrome`, or `PLAYWRIGHT_CORE` to the
module path when Playwright is installed elsewhere.

Generate names from the core directly:

```js
import { readFileSync } from 'node:fs';
import { loadLap, parseLpp, generate } from './core/index.js';

const packs = ['ancient-babylonian', 'aztec'].map((id) =>
  loadLap(readFileSync(`packs/${id}.lap`, 'utf8')),
);
const preset = parseLpp(readFileSync('presets/babylonian-aztec-50-50.lpp', 'utf8'));

console.log(generate({ laps: packs, preset, category: 'person', count: 5 }));
```

See the [authoring guide](docs/lap-authoring-guide.md) and
[plugin API](docs/plugin-api.md).
